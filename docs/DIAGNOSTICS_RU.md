# Диагностика KeybindBridge 1.0.0

Штатный релизный режим — `FeatureLevel=8`. Если
`KeybindBridge.diagnostics.ini` отсутствует, DLL автоматически выбирает уровень
8. MyGUI создаётся только после нажатия `End`, автономные расширения запускаются
через `luaL_loadbuffer`, а runtime работает только из подтверждённых клиентских
callback. Уровни `0–7` сохранены как аварийное отключение подсистем для поиска
причины вылета. Создавай `KeybindBridge.diagnostics.ini` рядом с
`keybind_bridge.dll` в `Release/DLLModules` только на время такой проверки.

## Порядок проверки

Перед каждым запуском полностью закрывай игру. При первом сообщении нового
процесса `KeybindBridge.log` очищается автоматически.

### Запуск 1 — только при проблеме на штатном уровне 8

```ini
[Diagnostics]
FeatureLevel=0
```

Это API и hook рабочей версии 0.8 без сканера и автономного runtime. Загрузи
тестовый мир и побудь в нём 15–20 секунд.

### Запуск 2 — только если первый не вылетел

```ini
[Diagnostics]
FeatureLevel=1
```

Добавляются расширенный реестр действий и поиск `keybindbridge.json`, но никакой
Lua-файл автоматически не выполняется.

### Запуск 3 — только если второй не вылетел

```ini
[Diagnostics]
FeatureLevel=2
```

DLL только сохраняет ссылку на Lua-окружение. Никакие Lua-функции и runtime не
вызываются.

### Запуск 4 — только если уровень 2 не вылетел

```ini
FeatureLevel=3
```

После исходного игрового вызова DLL проверяет `sm.isServerMode()`, но не вызывает
`dofile`. В логе появятся строки `TRACE: client environment guard ...`.

### Запуск 5 — только если уровень 3 не вылетел

```ini
FeatureLevel=4
```

DLL компилирует и выполняет через `luaL_loadbuffer` один безопасный Lua-фрагмент,
не создающий runtime или GUI. В логе должна появиться строка
`TRACE: native Lua loader probe completed`.

### Запуск 6 — только если уровень 4 не вылетел

```ini
FeatureLevel=5
```

Выполняется настоящий `KeybindRuntime.lua`, но он создаёт лишь пустой runtime.
Опрос клавиш, MyGUI и автономные расширения ещё не включаются. В логе должна
появиться строка `OK: KeybindBridge client runtime started`.

### Запуск 7 — только если уровень 5 не вылетел

```ini
FeatureLevel=6
```

Включается базовая логика runtime и опрос клавиш, но не MyGUI и не расширения.

### Запуск 8 — только если уровень 6 не вылетел

```ini
FeatureLevel=7
```

MyGUI не создаётся при загрузке мира. После появления персонажа нажми `End`:
только тогда runtime попробует создать и открыть меню. Внешнее Win32-окно на
этом уровне полностью отключено. Автономный фонарик ещё не загружается.

### Запуск 9 — только если уровень 7 не вылетел

```ini
FeatureLevel=8
```

Полная штатная конфигурация. DLL загружает найденные расширения через
`luaL_loadbuffer` в тот же sandbox, что и ядро. Их клиентские callback-функции
ждут появления локального игрока, а MyGUI — первого `End`. Внешнее окно и
игровой `dofile` не используются.

## Что прислать

Для каждого проверенного уровня нужны:

- номер `FeatureLevel`;
- результат: мир загрузился или игра вылетела;
- отдельные `KeybindBridge.log` и игровой лог.

Стартовая строка обязана содержать выбранный уровень, например:

```text
OK: KeybindBridge 1.0.0 initialized; FeatureLevel=1
```

Если строка показывает другой уровень, игра прочитала не тот INI или загрузила
другую DLL.
